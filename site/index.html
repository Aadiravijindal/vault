The problem

Every AI tool in your company keeps its own private notepad — and anything that reaches it becomes something it believes.

A supplier's email says the discount ceiling is 60%. A scraped page carries an instruction dressed as a sentence. A copilot infers a customer is churning and, three weeks later, no one can tell that from a fact somebody actually stated.

The memory is where that lands, so the memory is where it has to be stopped. Vault puts one shared memory behind a gate that every agent writes through, and a recorder that never stops.

The gate

Ten checks on every write, from every agent, forever.

There is no fail-open. The fail-safe posture is queue-and-drain or reject — pass unchecked is not a configuration option, because no code path exists for it.

  1. 01Identity & authorisationunregistered agents, expired or wrong-origin credentials, out-of-scope writes
  2. 02Channel trustdeny-by-source: email, web forms, scraped pages, other agents' output
  3. 03Source verificationunauthenticated senders, lookalike and homoglyph domains, first contact
  4. 04Private information45 detectors — credentials blocked outright, never masked-and-stored
  5. 05Sensitivity labellingnever guesses downward; unsure → higher label, then review
  6. 06Wallscross-department writes blocked and alerted, never silently dropped
  7. 07Instruction detectionseven layers; any one firing holds the write
  8. 08Policy rulesplain language → policy-as-code, backtested before enabling
  9. 09Reconciliationcontradictions resolve by authority, not recency
  10. 10Consent & lawful basisno personal data without a recorded basis

Why “authority, not recency”

“Newer wins” was the bug. A stranger's email is always newer than your CFO's approval.

  1. approved (golden) beats everything
  2. verified by a human beats unverified
  3. trusted channel beats untrusted
  4. higher org authority beats lower
  5. more specific beats general
  6. corroborated beats single-source
  7. only then: newer beats older

The proof problem

A hash chain you control proves nothing to an adversary.

Opposing counsel will say you own the server and you own the chain. So the chain is only the first of five layers.

Internal hash chain

Tamper-evidence, for you.

Customer-held keys

The customer proves integrity, not the vendor.

External anchoring

Periodic digests to independent append-only witnesses.

Witness diversity

More than one, so no single witness can be leaned on.

Standalone verifier

Imports nothing from the product. Your auditor trusts neither party.

What this proves: no entry was altered, removed or reordered after it was written, and every signed entry was signed by the holder of the private key.

What it does not prove: that the facts recorded are true. It proves what was recorded, and that the record has not changed since.

The model layer

The model may arrange the memory. It may never decide who can read it.

A folder is a wall.

It decides who can read what. So the model can never invent one — it proposes, with evidence, and a named administrator approves. “Who approved this category, and when” is the question an auditor asks, and “the model decided” is not an answer.

A tag is an index.

It decides what is easy to find, and every read through one is still resolved against the folder wall underneath. So the model invents these freely — client, project, risk. Full freedom on exactly the side that isn't a breach.

It runs on your hardware

Classifying a payroll line with a hosted model is a disclosure, not a latency question. Point Vault at Ollama and the weights and the text never leave the building. No API key, no per-token bill.

It never blocks a write

The gate publishes a latency budget — p50 80ms — and a model call is hundreds of milliseconds. Rules file every fact instantly; the model refines afterwards. A model outage is never a write outage.

It learns, in one small file

What filing has learned about your company: counts and vocabulary, never claim text. Consulted before any model call, which is why most facts are filed without one. Signed, so an edit cannot be hidden.

The record

“Show me everything that ever happened to this record, and who did it.”

That is the question a regulator actually asks. Every action carries who, what, when, where, why, how, and what changed — field by field.

Refusals are recorded as loudly as successes

A log of things that worked describes a system nobody attacked. Wall hits, refused questions, blocked writes and reads that returned less than was there are the entries an investigation actually turns on.

An export states its own completeness

A selective extract presented as a full one is the oldest way to mislead an auditor using nothing but true statements. Every bundle says how much of the record it contains, how much it does not, and is signed over its own contents.

What Vault does not do

The list a vendor usually leaves out.

  • It does not read minds. A fact nobody said in a channel Vault can see is a fact Vault does not have.
  • It does not make an AI truthful. It makes what the AI believes attributable, and wrong beliefs traceable.
  • It does not catch every attack. It publishes its catch rate, runs the suite continuously, and alerts when the number falls — including when it falls and still passes.
  • It does not prove a fact is true. It proves what was recorded, and that the record has not changed.
  • It cannot see inside a tool it is not connected to. Every connector says what it cannot pull, on the card, before you buy.

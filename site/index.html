Our approach

Governance beats cleverness.

Vault is a closed system — gate, store, walls, ledger and an optional model — engineered together for one job: being the memory an enterprise can actually put its name to.

  1. Step 01

    Deterministic rules decide first.

    Ten checks, all of them explainable, none of them probabilistic. A write is filed within a published latency budget and behind a wall before anything slower is allowed an opinion.

  2. Step 02

    A model refines, off the write path.

    Semantic filing runs afterwards, on your own hardware if you want it. It may move a fact between folders that exist and raise a label. It may never create a folder, lower a label, or touch a golden fact.

  3. Step 03

    Everything is recorded twice.

    A sealed ledger that is content-free and provable, and a journal that holds the detail — cross-referenced, so an auditor can verify the chain and read what actually happened, and check the two agree.

Where the time goes

Gate, deterministic 80 ms p50
Memory recall <1 ms
Local model call 0.7–4 s off the write path
Hosted model call 0.4–1 s and a disclosure

This is the whole argument for the ordering. A model in front of the gate turns a model outage into a write outage; a model behind it costs nothing when it fails.

Stops the write, not the incident report.

Instruction detection runs seven ways and any one firing holds the write. A message carrying a payload contaminates everything extracted from it — because splitting poison across a message is how a benign fact gets planted.

Approved beats verified beats trusted-channel beats corroborated beats newer. "Newest wins" was the bug: a stranger's email is always newer than your CFO's approval.

Golden, verified, guessed — with the source, the channel and the age. The agent sees the label, which is the difference between an assertion and an unconfirmed signal.

What Vault does not do

The list a vendor usually leaves out.

  • It does not read minds. A fact nobody said in a channel Vault can see is a fact Vault does not have.
  • It does not make an AI truthful. It makes what the AI believes attributable, and wrong beliefs traceable.
  • It does not catch every attack. It publishes its catch rate, runs the suite continuously, and alerts when the number falls — including when it falls and still passes.
  • It does not prove a fact is true. It proves what was recorded, and that the record has not changed.
  • It cannot see inside a tool it is not connected to. Every connector says what it cannot pull, on the card, before you buy.

FAQ

Frequently asked questions.

Does it need an internet connection?

No. Vault runs from a fresh clone on Node 22 with no dependencies and no build step. Connectors reach out if you configure them; the gate, the store, the ledger and the console do not. An optional model can run on your own hardware, so even semantic filing stays inside the building.

Where does our data live?

Wherever you put it. On-prem, in your cloud, air-gapped. Folders can be pinned to a region and cross-border reads are refused rather than logged after the fact. Encryption keys can be yours, held in your own KMS.

What happens when the AI gets something wrong?

The fact is superseded, never deleted, and the losing version stays in history. Then you can see who read it while it was live, what they did because of it, and what was derived from it — and undo those too. The undo is itself logged and reversible.

Can an administrator read everything?

No, and that is deliberate. There is no admin bypass anywhere in the product. Break-glass exists, needs two named humans, a stated reason and a time box, and it is loud in the ledger. Some folders need a separate approval chain even then.

How do we prove any of this to an auditor?

Export the ledger and run vault-verify, which imports nothing from the product. It recomputes every content hash, every chain link, sequence continuity, signatures against your public key, and the anchor digests. It also states plainly what it does not prove.

What if we want to leave?

Export everything, any time, at any volume, unthrottled, in an open format with the schema written into the export — plus instructions for standing the whole thing up without us. Migration tooling goes both ways.
